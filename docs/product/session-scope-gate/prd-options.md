# 会话隔离方案比较

## A. 仅在 RuntimeSyncBridge 中重置 owner

优点：改动最小。

缺点：`file://`、运行时关闭或请求未完成时不会触发；旧快照仍可能在页面中短暂可见。

结论：不采用。

## B. AppShell 会话门禁加 owner 重置（采用）

AppShell 在获取认证结果后，先依据 owner/dataScope 重置不匹配运行态，再允许业务路由渲染。检查中、匿名和失败状态展示非业务入口。

优点：覆盖 Web、Android WebView、服务端运行时关闭和异步认证窗口；不触碰后端协议。

代价：首次进入远端应用要等待一次会话确认。

## C. 按账号拆分 localStorage 键

优点：可在同一浏览器长期保留多账号离线缓存。

缺点：账号身份在 hydration 前未知，仍需门禁；迁移、清理和存储额度策略更复杂。

结论：后续有明确离线多账号需求时再评估。
