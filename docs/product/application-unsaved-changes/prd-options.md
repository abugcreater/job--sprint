# 机会编辑未保存修改保护方案比较

日期：2026-07-26

| 方案 | 做法 | 优点 | 风险与结论 |
|---|---|---|---|
| A. 保持直接退出 | 继续让取消和关闭按钮立即重置草稿。 | 无实现成本。 | 与用户编辑预期冲突，会无提示丢失输入，不采用。 |
| B. 机会编辑器内确认 | 对新增和编辑草稿做精确比较，仅在取消和移动端关闭时显示“继续编辑 / 放弃修改”。 | 覆盖已证实的高频丢失入口，不改变保存、数据模型或 URL 主链路，可用页面测试验证。 | 不是全局表单协议，不拦截刷新或外部导航，推荐。 |
| C. 全局路由与浏览器拦截 | 抽象所有表单的 dirty state，拦截路由、刷新和 WebView 返回。 | 覆盖面最大。 | 要统一多个模块、Android 返回和无障碍焦点规则，超出当天小步迭代，后续独立规划。 |

裁决：采用方案 B。先消除机会记录这一条已记录在产品文档中的直接数据丢失路径，不把局部确认伪装成完整全局草稿系统。
