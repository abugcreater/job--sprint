# 机会编辑未保存修改保护

日期：2026-07-26
状态：已完成，2026-07-26

## 需求卡

- 原始问题：机会工作台已支持新增、编辑和保存，但用户在输入后点击“取消编辑”或移动端关闭按钮会直接丢失本次修改。
- 目标用户：正在记录公司、岗位、JD 和招聘沟通事实的普通求职用户。
- 用户路径：机会工作台 -> 新增或编辑机会 -> 修改任意字段 -> 点击取消编辑或关闭编辑器 -> 选择继续编辑或放弃修改。
- 影响模块：React 机会工作台、机会表单、产品交互文档和页面测试。
- 数据对象：仅编辑器内的 `ApplicationFormDraft`；未确认前不写入 Evidence Gate、本地运行时或服务端。
- 权限与隔离：沿用当前用户的机会记录和 Evidence Gate 归属；不增加读取范围、账号能力或跨用户数据。
- 成功反馈：未修改时立即返回详情或列表；有修改时显示清晰的放弃确认，选择继续编辑保留所有输入，选择放弃才重置草稿并离开编辑器。
- 失败恢复：保存校验失败时留在编辑器并保留输入；确认面板不调用保存、删除、同步或 AI 生成。
- 验证层级：React 页面测试、类型检查、完整前端回归、浏览器桌面与窄屏走查、产品治理和敏感扫描。

## 本轮范围

1. 比较新增或编辑开始时的草稿与当前草稿，包含文本、状态和标签。
2. 为“取消编辑”和移动端“关闭机会编辑器”补未保存修改确认。
3. 未修改时保持现有直接退出行为；保存成功后保持现有读回行为。
4. 补覆盖新增、编辑、继续编辑和放弃修改的页面测试。

## 明确不做

- 不在本轮建立覆盖画像、知识边界、日程、复盘等全部模块的全局表单协议。
- 不拦截浏览器刷新、关闭标签页、应用强杀或所有外部路由跳转。
- 不自动保存、恢复草稿、增加服务端字段或修改 Android 打包与服务器配置。
