# 个人日程未保存修改保护方案比较

日期：2026-07-30

| 方案 | 用户结果 | 风险 | 结论 |
|---|---|---|---|
| 日程编辑器局部基线确认 | 只在两个已证实的草稿替换入口出现明确选择 | 范围小，能精确证明确认前不写入数据 | 采用 |
| 浏览器统一离页拦截 | 能覆盖部分刷新和关闭动作 | 无法解释当前页面内的编辑切换，也影响所有工作流 | 不采用 |
| 全局草稿协议与服务端草稿 | 可跨模块恢复 | 会改变数据模型、权限和 Android 行为，无法在当天完整验收 | 不采用 |

## 裁决理由

今天的可复现问题是日程表单内部的两次草稿替换。以局部基线和 `alertdialog` 修复，既能保留用户输入，也不会把未确认内容写入个人日程、今日行动或服务端同步层。
