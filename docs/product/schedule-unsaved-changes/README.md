# 个人日程未保存修改保护

日期：2026-07-30
状态：已完成（本地 React 验收）

## 需求卡

- 原始问题：用户新建日程时点击已有日程的编辑按钮，或编辑后点击“取消编辑”，当前草稿会被静默替换或清空。
- 目标用户：正在把当天求职行动安排进个人日程的普通用户。
- 用户路径：新建或编辑个人日程 -> 修改字段 -> 切换编辑另一条日程或取消编辑 -> 继续编辑或明确放弃修改。
- 影响模块：React 教练页个人日程、局部草稿适配层、确认面板、页面测试和产品运营文档。
- 数据对象：仅当前 `CoachScheduleDraft` 与内存基线；确认放弃前不写入、删除或同步个人日程和今日行动。
- 权限与隔离：沿用当前激活画像和其过滤后的个人日程；不读取其它画像或账号的数据。
- 成功反馈：未修改仍一步切换或取消；有修改时必须由用户选择“继续编辑 / 放弃修改”。
- 验证层级：草稿单测、React 页面真实交互、类型检查、前端回归、架构质量和敏感扫描。

## 本轮范围

1. 比较日程全部八个可编辑字段，并保存独立草稿基线。
2. 保护“编辑另一条日程”替换草稿的入口。
3. 保护“取消编辑”退出已有日程编辑态的入口。
4. 保存成功、删除当前编辑日程、切换画像或日期后刷新基线；未修改保持快速路径。

## 明确不做

- 不拦截浏览器刷新、关闭标签页、外部路由、Android 系统返回或应用强杀。
- 不保护删除另一条日程、日期切换、画像切换以外的离开动作，也不建立全局表单协议。
- 不自动保存、不增加服务端草稿、不修改 Android 包、服务器或远端配置。
