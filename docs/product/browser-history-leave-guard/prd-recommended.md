# 推荐方案

## 用户流程

1. 用户在已接入的表单编辑内容，页面通过 `useRouteLeaveGuard(true)` 注册脏状态。
2. 用户点击通往另一页面的站内链接、浏览器后退或浏览器前进。
3. 数据路由在提交导航前调用 `useBlocker`：无脏草稿直接通过；有脏草稿则停留在当前路由并展示已有确认面板。
4. 用户选择“继续编辑”时，守卫重置本次导航；若来源是站内链接，焦点回到该链接。
5. 用户选择“放弃修改并离开”时，守卫只放行已暂停的那一次导航。

## 实现约束

- `RouteLeaveGuardProvider` 仍只保存布尔 dirty 回调，不能读取、序列化或上传表单字段。
- 仅 pathname 改变才进入全局守卫；同页 query/hash 用于编辑器、筛选或视图状态时，保留页面自己的确认逻辑。
- Android 的 `jobsprint:android-back-pressed` 是独立入口，确认放弃后仍只调用既有无参数 bridge。
- 整页刷新、关闭页签和跳转站外继续由 `beforeunload` 负责；它们不属于 SPA 路由阻塞器。
- Hash URL 格式、可见路由、权限可见性和数据域不变。

## 验收标准

- 脏草稿下 `navigate(-1)` 不改变当前路由，显示确认面板。
- 选择继续编辑后仍在原路由且草稿状态保留。
- 再次历史返回后选择放弃，恰好到达目标历史路由。
- 无脏草稿的历史导航保持快速路径。
- 原有链接、`beforeunload` 和 Android 返回回归继续通过。
