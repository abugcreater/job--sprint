# Android 系统返回未保存内容保护审阅与裁决

日期：2026-08-02

## Dispatch

- 状态：`MANAGER_DISPATCH_PASS`
- Owner：Team Lead（主线程）
- 专家：无。当前线程处于 quarantine，按规则 `max_agents=0`。

## 观点

| 视角 | 结论 |
|---|---|
| 产品 | Android 用户应得到与站内链接一致的“继续编辑 / 放弃修改”选择，避免系统返回静默丢失输入。 |
| 技术 | 用可取消 DOM 事件表达网页是否接管返回；原生在未接管或确认后只完成一次真实返回，避免 history 伪造。 |
| 安全 | JS bridge 必须最小化，不能暴露账户、配置、文件或网络能力。 |
| QA | 必须分别证明脏草稿接管、继续编辑、确认放弃、干净返回和桥注册结构。 |

## 裁决

采用“单次协商 + 最小桥”方案。浏览器历史、强杀和草稿恢复没有可验证的统一产品语义，保留在已知问题中，不在本次假装解决。
