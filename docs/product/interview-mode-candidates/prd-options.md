# 方案比较

| 方案 | 好处 | 风险 | 结论 |
|---|---|---|---|
| A. 保留切换按钮，只改变视觉状态 | 改动最小 | 用户会误以为已切换练习范围，实际题目不变 | 不采用 |
| B. 用当前用户上下文生成本地规则题 | 无服务端依赖，来源可解释，可覆盖空 JD 情况 | 题目深度受已记录资料限制 | 推荐 |
| C. 每次切换请求 AI 生成题目 | 题目可更丰富 | provider、延迟、失败与数据边界会阻塞基础练习 | 不采用 |

## 裁决原则

题型切换必须带来可见、可解释的题目变化。当前资料不足时应说明降级来源，不以默认 Java 题或其他用户资料填充。
