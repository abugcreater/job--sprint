# 复盘编辑未保存修改保护方案比较

日期：2026-07-29

## 方案 A：仅保留“取消编辑”直接清空

- 优点：无新增代码。
- 缺点：用户无法判断取消会丢失刚写的复盘，且 Evidence Gate 编辑路径没有恢复选择。
- 结论：不采用。

## 方案 B：复盘编辑器局部基线确认

- 做法：打开本机复盘时记录基线；点击“取消编辑”时比较当前草稿，存在修改就先显示确认，只有放弃后才清空草稿与编辑状态。
- 优点：精确覆盖已确认的数据丢失动作，不扩大同步、权限和路由边界；与机会、画像的确认语义一致。
- 缺点：不覆盖其它离开路径或其它表单。
- 结论：推荐。

## 方案 C：统一离页守卫与服务端草稿

- 优点：理论上能覆盖刷新、路由和多个表单。
- 缺点：需要统一 React 路由、Android 返回、所有草稿状态和服务端恢复合同，当前无法在一天内安全验收。
- 结论：本轮不做，保留为后续专题。
