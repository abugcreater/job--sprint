# 画像未保存修改保护审阅与裁决

日期：2026-07-28

## 已确认事实

- `useProfileRecovery` 的新建、激活和编辑处理会直接调用 `setProfileDraft` 或 `activateUserProfile`。
- `CoachPage` 会在活跃画像变更时重建草稿，因此切换动作会覆盖当前输入。
- 现有删除确认保护的是持久画像及关联数据，不能替代未保存草稿保护。

## 裁决

采用方案 B。待处理动作在页面层保存，只有用户明确放弃后才调用原处理器；画像草稿比较放在 `coachAdapter`，避免 UI 层散落字段判断。

## 安全与边界

- 确认面板不得保存草稿、切换账号、生成 AI、修改 Evidence Gate 或调用远端接口。
- 仅当前用户的内存草稿参与比较；不会读取其他数据域。
- 快速建档向导有独立状态，本轮不混入其流程。
