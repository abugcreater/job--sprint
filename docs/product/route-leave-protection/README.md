# 未保存内容的路由离开保护

日期：2026-08-01
状态：已完成（本地 React 验收）

## 需求卡

- 原始问题：画像、知识边界、日程、机会和复盘已有局部“取消/替换草稿”确认，但用户点击侧栏、移动端底部导航或页面内模块链接时，`HashRouter` 会卸载页面，内存草稿会直接丢失。
- 目标用户：正在连续填写求职资料、机会记录或复盘内容的普通求职用户。
- 用户路径：填写任一受保护表单 -> 点击站内模块导航或页面内跳转 -> 继续编辑，或明确放弃修改后离开。
- 影响模块：React `AppShell`、HashRouter 站内链接、五类既有草稿保护、浏览器离开事件、回归测试和产品运营文档。
- 数据对象：仅当前页面内尚未保存的草稿；确认前不写入画像、日程、Evidence Gate、AI 反馈或服务端。
- 权限与隔离：只读取页面已经持有的本地 dirty 状态；不读取账号、其它画像、其它数据域或管理员数据。
- 成功反馈：站内跳转有未保存内容时显示统一确认；继续编辑保留输入，放弃后才离开。刷新、关闭页签和跳往登录页等浏览器离开场景使用浏览器原生提示。
- 验证层级：统一守卫单测、既有页面回归、类型检查、前端回归、构建、架构与敏感扫描。

## 本轮范围

1. 让画像、知识边界、日程、机会和复盘向 AppShell 注册实时 dirty 状态。
2. 拦截当前 React 应用内 `#/...` 链接，用统一确认面板决定是否离开。
3. 在至少一个草稿未保存时为浏览器 `beforeunload` 注册原生提示。
4. 保持各模块既有取消、保存、删除、数据域与 AI 反馈逻辑不变。

## 明确不做

- 不以脆弱的 history 回滚伪造拦截浏览器返回、Android 系统返回、应用强杀或进程回收。
- 不自动保存、不恢复草稿、不增加服务端字段、不修改 Node/Rust/Android 包、服务器或远端配置。
- 不替代已有局部确认面板，也不扩大为跨设备草稿同步协议。
