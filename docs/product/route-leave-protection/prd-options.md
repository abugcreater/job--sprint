# 未保存内容路由离开保护方案比较

日期：2026-08-01

| 方案 | 说明 | 优点 | 风险与不足 | 结论 |
|---|---|---|---|---|
| 每个页面单独拦截导航 | 在五个页面复制侧栏、底栏和页面链接的处理 | 改动表面直接 | 易漏新入口，确认语义分叉，无法覆盖所有页面内链接 | 不采用 |
| 切换到 data router 并使用 `useBlocker` | 重写 HashRouter 路由基础设施 | 可得到 Router 原生阻断 | 需要迁移当前 HashRouter、鉴权回跳和测试基线，超出每日小步范围 | 暂不采用 |
| AppShell 注册表 + 链接捕获 + `beforeunload` | 页面注册 dirty 状态，AppShell 拦截站内 hash 链接，浏览器负责外部离开提示 | 覆盖现有站内链接，单一交互，改动不触碰持久化或权限 | 不覆盖浏览器/Android 系统返回 | 推荐 |
| 自动保存或服务端草稿 | 离开前保存并在下次恢复 | 可跨设备恢复 | 会改变保存语义、数据隔离、冲突和删除规则，需要独立产品设计 | 不采用 |

## 约束

- 当前项目使用 `HashRouter`；站内 React 链接输出为 `#/...`，不是浏览器整页离开。
- 现有草稿均是页面内状态，只有用户点击保存才进入正式数据与同步链路。
- 不能把浏览器原生拦截说成 Android 系统返回或草稿恢复已完成。
