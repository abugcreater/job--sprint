# 推荐方案：账号数据域唯一性合同

## 行为合同

| 操作 | 目标数据域 | 预期结果 |
|---|---|---|
| 新建账号 | 默认登录名，且未被占用 | 创建账号和邀请记录 |
| 新建账号 | 已被其他登录账号使用 | `409 data_scope_conflict`，不写入账号或邀请记录 |
| 重置同一账号密码 | 保持自己的原数据域 | 允许重置，不改变数据域 |
| 更新账号 | 改为其他账号的数据域 | `409 data_scope_conflict`，不写入配置 |

## 错误恢复

错误会返回冲突的登录账号及提示“数据域已被其他登录账号使用；每个邀请账号必须使用独立数据域”。owner 可保留表单输入，改用新数据域或先人工核对历史 users file。

## 关键约束

1. `dataScope` 为空时仍回退为当前 `username`，这是每个新账号的安全默认值。
2. 只排除同一 `username`，不能因为显示名、邀请批次或角色相同而共享数据域。
3. 邀请记录本身不是可登录主体；校验在 `provisionAccount` 触发时执行。
4. 不自动修复历史重复配置，避免猜错归属或迁移 runtime 数据；冲突必须显式暴露给 owner。
